# Proveedores e integraciones reales

Decisión del usuario del 23 de octubre de 2026: dejar todas las integraciones preparadas para producción y hacer las pruebas reales al final. Cada una tiene tres modos en Integraciones: apagada, simulación y real. El modo real sólo se puede elegir cuando el servidor tiene credenciales válidas en `/etc/culinaryos/integrations/<clave>.json` (dueño `root:culinaryos-app`, permisos `0640`; ejemplos en `deploy/integrations/`). Sin ese archivo nada sale de la sucursal. Un archivo inválido marca al proveedor con su error y no detiene el backend. Los secretos sólo están en esos archivos: ni la base de la sucursal ni los clientes los ven.

Reglas comunes: el dominio deja el trabajo en cola y el servicio de cada proveedor lo envía una vez, con arrendamiento y llave de idempotencia. Una respuesta perdida nunca se reenvía sin más: se consulta al proveedor por referencia y, si no hay forma, queda «sin respuesta» para que una persona decida. El dinero sólo se mueve cuando el proveedor confirma, con las mismas reglas del simulador (un pago que llega a una cuenta ya cubierta se devuelve).

| Integración (archivo) | Proveedor y API | Qué hace en modo real | Falta para producción |
|---|---|---|---|
| Facturación (`pac.json`, o el anterior `fiscal.json`) | Facturama API Web, sandbox o producción | Timbra, consulta, cancela y opcionalmente envía PDF/XML al receptor; nunca timbra dos veces | Cuenta de Facturama con el CSD del emisor, contrato con el PAC, claves SAT revisadas con el contador |
| Terminal bancaria (`terminal.json`) | Mercado Pago Point (Orders API), Clip (API PinPad), BBVA semi-integrado | Cobra en la terminal elegida, la consulta cada 3 s, cancela, devuelve un cobro sobre cuenta cubierta; BBVA se registra con la autorización del voucher | Terminales en modo PDV (Mercado Pago) o con la app PinPad (Clip); token y llaves; BBVA no publica API |
| Pagos en línea (`onlinepay.json`) | Stripe Checkout Sessions | Crea la liga, la manda por WhatsApp, la consulta cada 10 s, aplica el pago, reembolsa y expira | Cuenta de Stripe verificada y llave secreta |
| WhatsApp y correo (`messaging.json`) | WhatsApp Cloud API (Meta) y SMTP (MailKit) | Envía cada aviso con su plantilla aprobada y el correo por STARTTLS; reintenta sólo si no salió | Número verificado, plantillas aprobadas por Meta con las variables en el orden documentado, buzón SMTP |
| Plataformas de reparto (`aggregators.json` en la sucursal, `--deliverect-config` en el portal) | Deliverect | El portal recibe el pedido firmado (HMAC) y lo pasa a la sucursal; la sucursal acepta o rechaza, devuelve los estados 20/70/90/110 y publica el menú | Contrato y certificación con Deliverect, URL de producción, ids de canal de Uber Eats/Rappi/DiDi, Central publicada en internet |
| Hotel (`pms.json`) | Cloudbeds API v1.3 u Oracle OPERA por OHIP | Busca al huésped hospedado, valida apellido y crédito, publica el cargo y registra el pago a habitación | Llave de Cloudbeds o acceso OHIP del hotel, código de transacción del restaurante |
| Mapas (`maps.json`) | Google Geocoding y Routes | Ubica la dirección al guardarla y mide distancia y tiempo desde el restaurante | Clave restringida a esas dos API con facturación activa |
| Identificador de llamadas (`callerid.json`) | Asterisk AMI sobre TLS | Registra la llamada y la relaciona con el cliente por los últimos 10 dígitos | Conmutador con usuario AMI de sólo lectura y certificado |
| Impresora y cajón (`printer.json`, o el anterior `/etc/culinaryos/printer.json`) | ESC/POS en red o USB | Imprime cuentas y cortes, abre el cajón | Impresora y cajón físicos |

Sin cambio: FCM/APNs (notificaciones push) siguen aislados, y el pago en línea dentro de la PWA de pedidos web no está habilitado.

Fuentes revisadas el 23 de octubre de 2026: [Mercado Pago Point](https://www.mercadopago.com.mx/developers/es/docs/mp-point/payment-processing), [Clip PinPad](https://developer.clip.mx/docs/api-de-pinpad), [Stripe Checkout](https://docs.stripe.com/api/checkout/sessions), [WhatsApp Cloud API](https://developers.facebook.com/docs/whatsapp/cloud-api), [Deliverect](https://developers.deliverect.com), [Cloudbeds](https://developers.cloudbeds.com), [OHIP](https://github.com/oracle/hospitality-api-docs), [Google Routes](https://developers.google.com/maps/documentation/routes), [Facturama SDK](https://github.com/Facturama/facturama-php-sdk). Detalles que se confirman al probar con credenciales reales: el formato de menú y los ids de canal de Deliverect, si Mercado Pago devuelve los últimos 4 dígitos, y el endpoint OAuth del ambiente OHIP de cada hotel.
